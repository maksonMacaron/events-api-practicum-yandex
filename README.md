# Events API (ASP.NET Core Web API)

Простой REST API для управления мероприятиями.

---

## 🚀 Возможности

* Получение списка событий с фильтрацией и пагинацией
* Получение события по Id
* Создание события
* Обновление события
* Удаление события
* Создание брони с быстрым ответом `202 Accepted`
* Получение текущего состояния брони
* Подтверждение ожидающих броней фоновым сервисом

---

## 🧱 Технологии

* C#
* ASP.NET Core Web API

## 🔍 Фильтрация и пагинация

GET /events

### Query-параметры:

- title — поиск по названию (регистронезависимый)
- from — дата начала
- to — дата окончания
- page — номер страницы (по умолчанию 1)
- pageSize — размер страницы (по умолчанию 10)

Пример:

`GET /events?title=концерт&from=2026-06-01&page=1&pageSize=5`

## 🎟️ Бронирования

`Booking` содержит `Id` брони, `EventId` мероприятия, `Status`, время создания `CreatedAt` в UTC и время обработки `ProcessedAt` в UTC. До обработки `ProcessedAt` равен `null`.

Статусы:

* `Pending` — бронь создана и ожидает обработки;
* `Confirmed` — бронь подтверждена;
* `Rejected` — бронь отклонена. Этот статус предусмотрен моделью; текущий фоновый сервис подтверждает все ожидающие брони.

### POST /events/{id}/book

Создаёт бронь для существующего мероприятия. Отвечает `202 Accepted`, возвращает бронь со статусом `Pending` в поле `data` и адрес для проверки состояния в заголовке `Location`. Если мероприятие не найдено, возвращает `404`.

### GET /bookings/{id}

Возвращает текущее состояние брони с кодом `200 OK`. Если бронь не найдена, возвращает `404`.

Сервис раз в секунду проверяет ожидающие брони. Для каждой делает задержку в две секунды, имитируя внешний вызов, затем устанавливает `Confirmed` и заполняет `ProcessedAt`. Брони и мероприятия хранятся в памяти приложения и исчезают после перезапуска.

### Пример через Swagger

1. Выполните `POST /events` с телом:

   ```json
   {
     "title": "Концерт",
     "startAt": "2026-10-01T18:00:00Z",
     "endAt": "2026-10-01T20:00:00Z"
   }
   ```

2. Скопируйте `data.id` созданного мероприятия и выполните `POST /events/{id}/book`.
3. Убедитесь, что ответ имеет код `202`, заголовок `Location` указывает на `/bookings/{bookingId}`, а `data.status` равен `Pending`.
4. Откройте `GET /bookings/{bookingId}` сразу после создания, затем повторите запрос через несколько секунд. Статус изменится на `Confirmed`, а `processedAt` получит время обработки.

## ❌ Ошибки

Если событие или бронь не найдены, соответствующий эндпоинт возвращает `404`:

```json
{
  "success": false,
  "statusCode": 404,
  "message": "Событие по Id [...] не найдено"
}
```
